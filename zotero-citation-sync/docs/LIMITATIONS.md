# 技术限制与未完成事项

## 当前交付边界

- Mac 启动器与应用包尚未在 Mac 运行；当前版本不是已经验收的 Mac Word 全自动同步工具。
- 没有实现程序控制 Zotero 官方 Word 插入对话框、自动 Refresh 或完整一键批量写入。工作台产生核对任务与副本，正式引文通过使用者在 Word 操作。
- 只读结构检查能检出字段损坏、文本伪装、未授权新增及内容变化，不能独立证明 Word/Zotero 可编辑性。`verified_by_user` 明确表示结构检查加使用者实际操作确认。
- 不使用 Office JS 自制字段，不重建 DOCX，不通过 python-docx 重写整篇稿件，不写 Zotero SQLite。
- 暂不提供 Zotero 菜单入口、SwiftUI 原生壳、签名/公证、自带 Python 或自动更新。界面是本机浏览器中的 Mac 风格布局。
- 首版保守识别显式引用请求；不保证任意自然语言评论都被识别。一个请求对应一篇文献和一个位置。
- 不调用远端大模型判断研究证据。摘要、来源片段仅供核对，必须由使用者阅读 B 并确认结论适配。
- 只匹配本地已有文献，不联网查询 Crossref/PubMed、不自动补全元数据或创建文献。缺少身份进入待确认。
- 原始数值 item ID 不足以证明可移植身份，字段需含可识别的 Zotero item URI。旧文档仅保存本地 URI、文库变更或条目合并时可能需要人工处理。
- 应用接口支持个人/群组文库路由，但当前界面只使用个人文库。全量读取上限 100000 项，每页 100，扫描时文库版本改变就停止。
- 已同步请求后来改变、撤回或删除会保留冲突。可确认保留文档现状，或将修改后的有效请求重新核对为新增引用；自动修改/删除 Word 旧引文仍未实现。

## 内容保护的保守行为

支持读取复合 Zotero `ADDIN ZOTERO_ITEM CSL_CITATION` 字段及文末 `ZOTERO_BIBL`。书签存储、simple-field Zotero 字段、跨段落引文、结构异常和修订中的目标段落会要求人工核查。

只定位正文精确原句；不自动向页眉、脚注或尾注插入。存在这些对象的稿件可以读取与备份，保存后会检查它们是否变化。Word 在打开和保存时可能正常重排 XML、更新样式或脚注缓存；严格检查会产生保守拒绝。不得用“忽略错误”确认通过，应保留两份文件并调查差异。

既有样式、关系、嵌入对象、表格结构、修订身份及批注锚点均受检查。新增参考文献可能导致自然分页变化；程序没有渲染版式比对，必须人工逐页核对。文末参考文献存在性与 CSL 元数据有结构检查；条目与文内一致性还需官方 Refresh 和人工复核。

原稿必须先保存；无法读取 Word 尚未保存的编辑缓冲区。准备和验证均核对磁盘哈希，文库发生任何版本变化也要求重扫，可能比必要范围更严格。

## 中断及恢复

只创建新文件，不原位替换原稿。磁盘写入失败可能留下尚未登记的目录或部分副本，应用不会把它标为已完成。每个阶段保留文件，便于人工审计。

0.1.1 在更新状态和任务记录之前保存提交日志，再逐一原子替换各 JSON。中断后可以按日志重放未完成的记录；已应用的文件不会重复生成任务。所有目标必须处于原指纹或预期新指纹状态，备份和待登记的已验证副本也需通过核对。提交回执独立保存，是恢复后的审计依据。

跨进程互斥使用操作系统锁，并保留与旧版互斥的 PID 标记。恢复只会归档能证明所属进程已退出的遗留标记；PID 正在运行、被复用或无法确认时不会解锁。`OPERATION_IN_PROGRESS` 应先在“中断恢复”检查，不要删除状态或强行移除运行中进程的锁。

没有日志的旧版不一致、损坏的日志/状态、写入前留下的孤立目录，以及原文件被外部修改等情况不会自动修复。状态 JSON 损坏绝不会被重建为空历史。当前通过了 Windows 实际进程退出和磁盘错误注入测试；断电、文件系统损坏及 Mac 锁实现尚未实测。

恢复按钮验证原备份哈希，生成新的恢复副本。它不会把改后的 Word 保存缓冲区撤销，也不会撤销 Zotero 中的手动编辑。

## 隐私与运行边界

应用的数据请求仅允许字面地址 `127.0.0.1`，拒绝重定向和代理，采用 GET；界面服务绑定回环地址，有每次启动的随机令牌、Host/Origin 校验及限制外连的 CSP。它不抵御已经能读取本用户文件的其他本地程序。Mac 数据目录权限为当前用户专用，文件不另外加密。

本次测试验证了回环 HTTP、拒绝外部地址/重定向、日志不含正文及构建排除私有数据；未做操作系统级的全流量抓包，也未完成 Mac 断网环境验收。Zotero/Word 自身同步行为不作改变。
